# Introduction:

## What is Version Control System (VCS)?

- "VCS" most commonly refers to a Version Control System, is a tool used to track and manage changes made to files, folders, and source code over time.
- This tool facilitates collaboration among developers. 

It helps developers:
- Store different versions of files
- Track changes
- Restore old versions
- Work together as a team
- Avoid overwriting each other's work

---

## Why VCS is Important?

Without VCS:
- Changes can be lost
- Difficult to track file history
- Team collaboration becomes hard
- No backup of previous versions

With VCS:
- Easy to manage project history
- Multiple developers can work together
- Easy rollback to previous versions
- Better project management

---

## Features of VCS

- Tracks file changes
- Maintains history
- Supports collaboration
- Backup and recovery
- Branching and merging
- Version comparison

## Types of Version Control System (VCS)

Version Control System (VCS) is mainly divided into 3 types:

1. Local Version Control System (LVCS)
2. Centralized Version Control System (CVCS)
3. Distributed Version Control System (DVCS)

---

## 1. Local Version Control System (LVCS)

- In Local VCS, all version history is stored in the same local computer 
- Only one user mainly works on the project.
- It stores versions locally & no internet required
- Easy for single-user projects and Fast access
- No team collaboration also data loss happens if system crashes
- Example - RCS (Revision Control System)

## 2. Centralized Version Control System (CVCS)

- In CVCS, all files and history are stored in a central server.
- Developers connect to the server to work on the project.
- Multiple developers can collaborate together.
- Internet or network connection is required.
- If the server fails, all users are affected.
- Backup management becomes easier because everything is stored in one server and also the Performance may slower compared to DVCS.
- Examples: SVN, CVN

## 3. Distributed Version Control System (DVCS)

- In DVCS, every developer has a complete copy of the repository and history.
- Developers can work offline and sync changes later.
- Each developer stores a complete repository locally, can work without internet, and later upload changes to the remote server by using git commands.
- Faster compared to CVCS.
- No single point of failure.
- Better backup and recovery.
- Examples: Git, Mercurial


## Difference Between CVCS and DVCS

| CVCS | DVCS |
|------|------|
| Central server required | Full copy for each user |
| Mostly online work | Offline work possible |
| Slower | Faster |
| Single point failure | Better backup |
| Example: SVN | Example: Git |

  ### Note:

- LVCS is suitable for individual use
- CVCS is suitable for centralized team management
- DVCS is most popular today because of speed, flexibility, and offline support
