# Git Terminology

## 1. Repository (Repo)
A storage location where project files and version history are maintained.

- Contains files, folders, commits, and branches
- Can be local or remote
- Example: GitHub repository

---

## 2. Working Directory
The current project area where files are created or modified.

- Contains actual project files
- First place where changes happen
- Includes tracked and untracked files

---

## 3. Staging Area
Temporary area where changes are prepared before commit.

- Stores selected changes
- Changes added using `git add`
- Also called Index area

---

## 4. Commit
A saved snapshot of project changes.

- Stores changes permanently
- Each commit has unique ID
- Created using `git commit`

---

## 5. Branch
A separate line of development.

- Used for new features or fixes
- Helps developers work independently
- Default branch is usually `main`

---

## 6. Merge
Combines changes from one branch into another.

- Used after feature completion
- Integrates code changes
- Done using `git merge`

---

## 7. Clone
Creates a local copy of remote repository.

- Downloads complete repository
- Includes history and branches
- Done using `git clone`

---

## 8. Push
Uploads local commits to remote repository.

- Sends latest changes to GitHub
- Used for collaboration
- Done using `git push`

---

## 9. Pull
Downloads and merges changes from remote repository.

- Updates local repository
- Combination of fetch + merge
- Done using `git pull`

---

## 10. Fetch
Downloads latest changes without merging.

- Safely checks remote updates
- Does not modify local files
- Done using `git fetch`

---

## 11. Remote Repository
Repository hosted on remote server.

- Used for team collaboration
- Hosted on GitHub or GitLab
- Accessed through internet

---

## 12. HEAD
Pointer to current branch or latest commit.

- Represents current position
- Moves automatically after commit
- Usually points to main branch

---

## 13. Checkout
Used to switch branches or commits.

- Changes current working branch
- Helps move between versions
- Done using `git checkout`

---

## 14. Fork
Personal copy of another repository.

- Mostly used in open-source projects
- Allows independent modifications
- Common in GitHub

---

## 15. Conflict
Occurs when Git cannot merge automatically.

- Happens during merge or pull
- Requires manual fixing
- Common in team projects

---

## 16. Tag
Used to mark important versions.

- Mostly used for releases
- Easy version identification
- Example: v1.0

---

## 17. Origin
Default name of remote repository.

- Automatically created during clone
- Represents GitHub repository
- Used in push and pull commands

---

## 18. Main Branch
Default primary branch of repository.

- Usually named `main`
- Stores stable code
- Main development branch
